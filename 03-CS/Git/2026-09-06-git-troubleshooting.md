# Gitトラブルシューティング：Pull後のResetによるRebaseコンフリクト解消 (2026-09-06)

## 1. 発生した問題
- `rag-toy-project` リポジトリを `git pull` した後、コミットの誤りにより `git reset HEAD~1` を実行。これによりローカルのコミットポイントが過去の状態へ巻き戻った。
- その後、新たに作成したコミットをプッシュする際に `non-fast-forward` エラーが発生。

## 2. 原因分析

### 想定していた流れ vs 実際に起きたこと

| 区分 | 想定していたシナリオ | 実際のターミナルでの挙動 |
| :--- | :--- | :--- |
| **最初のPull** | Pullが正常に完了していないと思っていた | `7942e57` ➔ `daea3f5` へ正常に取得完了 |
| **Resetの実行** | （記憶にない、または単なるファイル取り消し目的） | ローカルの作業位置を過去（`7942e57`）へ巻き戻した |
| **Push拒否** | リモートに別の変更があったため拒否された | 過去の状態で新しいコミットを作成したため拒否された |
| **衝突の原因** | READMEを後からコミットしたため衝突 | 過去のREADMEとリモート最新のREADMEが重複し衝突 |
---
<br>
- `git pull` で取得した最新コミット（`daea3f5`）から、`reset` によって過去のコミット（`7942e57`）へ戻ってしまった。
- 過去の地点から新しいコミットを作成してプッシュしようとしたため、リモートリポジトリと履歴が分岐（乖離）してしまった。

## 3. 解決手順
1. `git pull origin main --rebase` を実行し、分岐した履歴の統合を試みる。
2. `README.md` でコンフリクト（衝突）が発生 ➔ 「受信変更の取り込み（Accept Incoming）」を選択して解消。
3. `git reset --soft` で誤って作成したコミットを整理後、`git rebase --continue` を完了させる。
4. `git push origin main` を実行し、正常にプッシュ完了。

## 4. 得られた知見（Lessons Learned）
- `git pull` を実行した直後には、安易に `git reset HEAD~1` を実行しない。
